> [!INFO] 如何高效、可控地虚拟化 CPU
> 操作系统必须以高性能的方式虚拟化 CPU，同时保持对系统的控制。

# 第六章  机制：受限直接执行

## 基本技巧:受限直接执行

- **直接执行**：直接在 CPU 上运行程序，速度快。
- **受限**：程序不能想干什么就干什么，危险操作必须交给 OS。

存在两个问题：

- **限制**：如何防止程序做不该做的事情？
- **控制权**：OS 怎么在程序运行时夺回 CPU 的控制权？

## 问题 1：受限制的操作

- **两种处理器模式**：
     - **用户模式**：不能直接与硬件交互。
     - **内核模式**：拥有特权，可以执行受保护的操作。

---

## 系统调用流程

用户程序想做特权操作，比如读文件、创建进程：

```text
用户程序
  -> libc 把系统调用号和参数放好
  -> 执行陷阱指令
  -> 陷入内核态
  -> 根据陷阱表找到处理程序
  -> 内核执行真正的系统调用
  -> 恢复用户现场
  -> 返回用户态
```

---

## 陷阱表

**陷阱表**在开机时由 OS 设置好，用户程序改不了。
它保存的是：

```text
陷阱号 -> 内核处理程序地址
```

这样用户程序只能通过 OS 开好的入口进内核，不能随便跳到内核里的任意位置。
