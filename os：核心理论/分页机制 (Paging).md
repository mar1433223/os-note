## 第18章：分页

> [!INFO] 核心问题
> 分段会产生外部碎片，那能不能把内存切得更规整一点？

---

### 为什么需要分页

[[地址转换机制|分段]]的段大小不固定，分配释放多次后会产生**外部碎片**。
明明总空闲内存够，但因为不连续，可能还是装不下一个新段。

分页的办法很简单：
别再按“段”这种不固定大小分配了，直接把虚拟内存和物理内存都切成**固定大小**的小块。

---

### 两个核心概念

- **页（page）**：虚拟地址空间切成固定大小的块（一般 4KB）。
- **页帧（frame）**：物理内存也切成同样大小的块。
- **页表（page table）**：记录虚拟页到物理页帧的映射。

虚拟页通过**页表**映射到物理页帧。

---

### 地址转换

虚拟地址分两部分：

```
虚拟地址 = VPN（虚拟页号） + offset（页内偏移）
```

转换过程：

```
VPN → 查页表 → PFN（物理页帧号）
物理地址 = PFN + offset
```

**offset 不变**，因为页和页帧大小一样。
变的只是“这一页放在哪个物理页帧里”。

---

### 执行一条指令的完整流程

```
1. PC里的虚拟地址 → 查页表 → 取出指令
2. 指令涉及内存访问 → 再查页表 → 取出数据
```

每条涉及内存的指令**最少访问两次内存**，性能有损耗 → 引出 [[TLB (翻译后备缓冲器)]]。

---

### 和分段对比


| 对比维度 | 分段 | 分页 |
| :--- | :--- | :--- |
| **切割单位** | 不固定 | 固定（**4KB**） |
| **碎片类型** | 外部碎片 | 内部碎片（页内浪费） |
| **转换方式** | **Base + 偏移** | 页表查询 |

---

### 缺陷

- 每次访存要多查一次页表，**速度慢** → [[TLB (翻译后备缓冲器)]]解决（第19章）。
- 页表本身可能很大，很多虚拟页根本没用到也要占表项 → [[多级页表]]解决（第20章）。

分页把外部碎片干掉了，但代价也很明显：
**地址转换变慢，页表本身也占空间。**
