
## 第15章 机制：地址转换

>[!info] 地址转换就是让看似美丽的虚拟现实转换为背后丑陋的物理事实

**1. 核心问题**

> OS 怎么把虚拟地址转换成物理地址，同时保证进程间隔离？

---

**2. Base & Bounds 机制**

- Base = 进程物理内存起始地址
- Bounds = 进程内存大小上限
- 物理地址 = 虚拟地址 + Base
- 虚拟地址 ≥ Bounds → 越界 → 触发异常

---

**3. 硬件做什么 / OS做什么**

| 角色      | 职责                                |
| ------- | --------------------------------- |
| 硬件（MMU） | 每次访存自动做地址转换和越界检查                  |
| OS      | 开机设置陷阱表；进程切换时更新Base/Bounds；处理越界异常 |

---

**4. 进程切换时**

- 把旧进程的 Base/Bounds 存入 PCB
- 把新进程的 Base/Bounds 从 PCB 加载进寄存器

---

**5. 缺陷** 中间堆栈之间的空闲空间也占物理内存，浪费 → 引出第16章分段。

## 分段 (Segmentation)

### 为什么需要分段
Base & Bounds 把整个地址空间当一个整体，堆栈之间的空闲空间也占物理内存，浪费。

### 核心思想
把地址空间拆成三个段，每个段有自己独立的 Base 和 Bounds：
- 代码段
- 堆段
- 栈段

### 地址转换流程
1. 取虚拟地址高2位 → 判断属于哪个段
2. 剩余位 = 段内偏移量
3. 偏移量 < Bounds → 物理地址 = 偏移量 + Base
4. 偏移量 ≥ Bounds → 越界，触发异常

### 栈的特殊处理
栈从高地址向低地址增长，越界判断方向相反：
- 段内偏移 = 偏移量 - 最大段大小（结果为负数）
- 物理地址 = Base + 负偏移（即从Base往下走）

### 地址空间布局
- 代码段：低地址
- 堆：从低往高增长
- 栈：从高往低增长

### 优点
每个段单独分配物理内存，中间空洞不占物理内存，解决了空间浪费。

### 缺陷
段大小不固定，分配释放后产生**外部碎片**，引出分页机制。
